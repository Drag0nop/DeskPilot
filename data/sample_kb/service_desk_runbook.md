# DeskPilot Demo Organization: IT Service Desk Runbook

This sample runbook demonstrates support procedures and priority definitions. It is fictional example content, not an operational policy.

## Email Troubleshooting
1. Confirm whether the issue affects one employee or multiple employees.
2. Check network connectivity and the service status dashboard.
3. For one employee, ask them to sign out and back in, check mailbox quota, and test the web client.
4. For a widespread issue, record affected teams and symptoms, then escalate as a suspected service incident. Do not ask every employee to reinstall their mail software.

## Laptop Performance
For a slow laptop, check CPU and memory use, available storage, startup applications, operating system updates, and endpoint security scan status. Do not disable security agents as a troubleshooting shortcut. Escalate if hardware diagnostics report a failure or repeated shutdowns continue after approved software remediation.

## Ticket Priorities
- **P1:** Company-wide outage or critical security incident. Start the incident escalation process immediately.
- **P2:** A major team is blocked and has no workable alternative.
- **P3:** One employee is blocked or degraded, with a limited workaround available.
- **P4:** Standard service request, information request, or low-impact issue.

## Ticket Details to Collect
Record the affected person or team, device asset tag when relevant, exact error text, approximate start time, steps already attempted, and business impact. Never request a user's password or multi-factor authentication code.
